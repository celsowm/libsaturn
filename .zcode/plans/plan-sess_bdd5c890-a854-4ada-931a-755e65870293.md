Debug & fix: missing PAD:/FRM: text in vdp2_rbg0_ground (YabaSanshiro)

## Root cause (primary suspect, strong evidence)

`examples/vdp2_rbg0_ground/main.c:61` — uncommitted change set `PAD_DEBUG_PALETTE` from `1u` to `0u`, contradicting its own comment at lines 58–60 ("the pad-debug text uses its own bank so uploading the font never disturbs bg_asset's palette").

Sequence in `main()`:
1. `sat_ascii_font_init_8x8_indexed8(..., PAD_DEBUG_PALETTE=0)` uploads the font palette (white at code 1) to **CRAM bank 0** (main.c:252)
2. `sat_vdp2_palette_upload(bg_asset.palette, 256, 0)` then **overwrites all of bank 0** with the ground texture palette (main.c:257)
3. Every glyph pixel (code 1) now resolves to `bg_palette[1] = 0xB615` — a muddy tan with the color-calculation bit set — instead of white, so the HUD text is effectively invisible in YabaSanshiro.

Supporting timeline: the Aug 3 10:15 build showed text (emulator_smpc_fix.png); the last main.c edit at 10:17 is this palette change; rebuilt ISOs after that have no text. Also confirmed ruled out: the SMPC SF-before-COMREG order matches the hardware manual; PRIR=6 < sprite priority 7 is correct for text-over-ground; erase stays transparent in this example so RBG0 shows (consistent with "scene shows, no text").
