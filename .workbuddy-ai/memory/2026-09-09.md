# 2026-09-09

## vdp2_rbg0_ground debug session

- **Root cause identified**: `sat_vdp2_wait_vblank_start()` is level-triggered and unbounded. The example was the only one in the repo using it. When TVSTAT.VBLANK stalled (emulator-specific), the CPU hung forever — no HUD, no pad polling, no camera movement.
- **Fixes applied**:
  1. `examples/vdp2_rbg0_ground/main.c`: switched to `sat_wait_vblank()` (edge-triggered + bailout), matching all other examples. Moved `sat_pad_poll()` to start of frame so camera moves same-frame. Added 2x yellow debug font. Lowered PRIR 7→6 so VDP1 HUD stays visible.
  2. `src/hal/vdp2.cpp`: added `kMaxVblankSpins` bailout to `wait_vblank_start/end` as defense-in-depth.
  3. `src/hal/smpc.cpp`: fixed INTBACK ordering — SF=1 BEFORE COMREG write, per hardware manual.
  4. `harness/tests/fixtures_good.json`: updated expected `prir` from 7→6.
- **Verification**: all 12 harness tests pass (1 skipped — BIOS baseline not present). Headless probe confirms sky/backdrop config correct (VRAM sky word 0x7F45 at 0x3FFFF, EWDR=0 transparent, PRIR=6). Pad read works (INTBACK succeeds, OREG0=0xF1). Camera moves on first iteration (`cam_y = -131072` with UP held).
- **Build toolchain gotcha**: PowerShell `PATHEXT` was corrupted (only `.CPL`), preventing `python` resolution in `build-example.ps1`. Fix: `$env:PATHEXT = "..."; $env:PATH = "C:\Python;$env:PATH"`.
- **Endianness gotcha**: SH-2 is big-endian (`-mb`). All WRAM dump reads must use `>I` / `>i` in Python, not `<I`.
