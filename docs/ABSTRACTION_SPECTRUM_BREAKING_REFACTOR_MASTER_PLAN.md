# LibSaturn — Abstraction Spectrum and Breaking Refactor Master Plan

**Status (2026-09-24):** M1–M5 have landed multiple tested implementation slices, including game-independent profiling, one global painter, texture-handle generation checks, staged VDP1 command-list rollback, split audio policies/service units, conservative physics candidate pruning, and build-variant isolation. Completed slices and remaining hardware/visual gaps are recorded below. The roadmap is not a declaration that every work item or on-device acceptance gate has passed.

**Policy:** Breaking changes are allowed across public headers, layouts, examples, tools, builds, and documentation. Remove displaced implementations and obsolete compatibility shims; preserve real hardware requirements, deliberate bare-metal access, bounded memory, and observable behavior. Each milestone must produce verifiable tests and usable examples. Do not treat a documentation-only change as completed implementation.

## 1. Non-negotiable philosophy: an optional spectrum of abstraction

LibSaturn must support several development styles equally, without forcing the engine onto bare-metal users:

- **L0: Direct hardware.** Explicit register/VRAM/CRAM/Sound RAM/DMA/Dual-SH2 control. No scene, asset registry, physics world, hidden frame loop, or mandatory heap.
- **L1: Independent primitives.** VDP1 command emission, VDP2 configuration, transfers, audio voices, CD, geometric and mathematical operations, and explicit task submission. The caller owns order and resources.
- **L2: Specialized reusable components.** Meshes, materials, animation, collision, physics, texture regions, streaming, view caches, render queues. Modules remain independently constructible and independently testable.
- **L3: Integrated optional runtime.** Scene, entities, camera, animation, physics, assets, global face sorting, overlay orchestration, and task scheduling, composed from the lower layers.

A lower layer MUST NOT depend on initialization, policy, data structures, or callback symbols from a higher layer. Static linking should pull in only required objects. High-level operations may adopt externally owned low-level resources through explicit borrowed/owned handles and lifetime rules. Raw VDP1 commands are never silently captured by the scene; mixing raw and scene submissions requires explicit frame passes and documented composition ordering.

**One implementation does not mean one API.** A direct draw path and a scene draw path may coexist, but geometry conversion, clipping, coordinate transforms, VRAM address math, and command encoding should have one shared implementation where semantics genuinely coincide. Global face sorting applies only to items submitted to the scene; raw draws retain caller-controlled order. Painter sorting cannot provide a general z-buffer or correctly resolve arbitrary intersecting polygons.

## 2. Ownership and dependency rules

- **SRP:** assets own identity/metadata; loaders own decoding; memory pools own allocation; textures own their GPU lifecycle; scenes own submission and visibility; renderer owns clipping, sort and emission; HAL owns register encodings and transfers. The scene coordinates but does not reimplement specialized services.
- **OCP:** introduce new colliders, geometry sources, material capabilities and backend-specific presenters through bounded typed data, static dispatch tables or narrow adapters. Avoid growing game-specific switches and avoid virtual dispatch where simpler C/static composition suffices.
- **LSP:** public capability and failure contracts must be equivalent across supported Master, Slave and software/fallback implementations. Do not falsely promise features a backend cannot provide.
- **ISP:** narrow public headers and independent component initialization. The umbrella header is convenience only. Keep internal painter keys, register shadow state and temporary face storage out of ordinary game-facing contracts.
- **DIP:** hardware drivers cannot invoke high-level audio/scene policy. A bounded cooperative-service hook owned by the runtime can service streaming during blocking CD waits without the CD driver knowing audio. Shared math belongs outside graphics so physics does not depend on rendering.
- **Memory:** explicit requirements/init APIs or caller-provided typed arenas; no mandatory heap, static initialization side effects, surprise per-frame allocations, unbounded data structures, hidden cross-SH2 cache sync or arbitrary copies.
- **Hardware:** keep numeric register values, bit fields, hardware widths and exact timing where required. Centralize and document their meanings, not every harmless zero/one. Separate hardware constants, validated algorithm limits, and user-configurable policy.

## 3. Cross-cutting contracts to freeze first

1. **Results:** distinguish submitted, prepared, culled, clipped, rejected for capacity, emitted, and deliberately skipped-as-unsupported. The frame exposes the first actionable failure and actual emitted-command counts; no unexpected error becomes a successful flush.
2. **Lifetimes:** define owned vs borrowed geometry/textures/palettes/materials, handles with generations, scene/frame scratch lifetime, and behavior when partially committed hardware transfers fail. Do not pretend that partial VRAM writes can always be rolled back.
3. **Coordinates/time:** one active resolution and one screen-to-native transformation used by all screen-space wrappers; explicit point-fixed conversion rules; shared clock for voice expiration and streams, with 50/60Hz modes supported only when video validation and hardware configuration genuinely support them.
4. **Capability:** document which features require VDP1, VDP2, Slave SH-2, RAM cartridge, or synchronization. Optional hardware must not become a requirement for primitive users.
5. **Constants:** name physical tolerances and geometry limits separately; check public painter-pass bounds before storing; represent CD command words and mask fields semantically. Never silently clamp user-facing render priorities.

## 4. Render and scene redesign

Build one optional L3 render plan for static cached faces, dynamic instances, meshes and specialized scene drawables: collect -> transform/animate only where needed -> cull/clip -> produce comparable painter keys -> globally order -> enforce budget -> emit to VDP1 -> explicit overlay/VDP2 composition. Cached projected geometry skips unnecessary work but enters the same global scene sort when used in L3. L1 direct draw stays immediate and independent.

Unify instance/material ownership and remove redundant per-batch sorting when the merge resorts globally. Provide bounded failure metrics and optional performance instrumentation. Preserve explicit low-level texture/command paths and document painter limitations for intersecting surfaces and VDP1/VDP2 layering.

## 5. Assets, texture transactions and storage

Normalize logical paths before comparing any registry entry and before publishing any manifest element. Preflight the entire bounded batch, including live-path collisions, capacity and invalid descriptors, so a rejected manifest does not partially register. Separate resource identity from residency (main RAM / VDP1 VRAM / SCSP). Split generic registry metadata from typed loaders and format-specific descriptors; design explicit borrowed-resource imports. Validate texture/palette updates before mutating logical state and expose a recovery state for irreversible partial hardware writes. Refresh only affected texture regions when hardware alignment permits.

## 6. Physics, audio, parallel, HAL

Split world stepping into integration, kinematic motion, broadphase, narrowphase/CCD, solver and pose update; make pair generation bounded and avoid repeating all-actor scans for each solver iteration. Separate voice manager, Sound RAM allocator, sound registry and audio clock. Remove the weak direct CD -> audio symbol dependency. Remove Skybridge-specific policy from generic parallel scheduling; make shared-buffer publication/invalidation and input/output ownership explicit, and compare Master/Slave semantic results. Keep HAL register writes isolated from rendering/game policies.

## 7. Delivery sequence and test gates

**M1 — Contracts and concrete integrity defects (in progress):** normalized asset duplicates, manifest preflight, active screen coordinates, painter-pass validation, accepted/skipped face counts, and direct-frame error reporting are implemented. The third slice shares a private scene-error contract across transformation lookup and asynchronous submission/merge. A valid pending task remains transient (SAT_ERR_BUSY); a failed task, invalid output, or rejected merge is recorded. Texture failure states now invalidate parent and all prepared regions on failed hardware writes and permit explicit full-update recovery. Palette rebinding now preflights without mutating the registry and commits only after a successful palette transfer; a failed transfer leaves previous logical ownership intact while marking the texture dirty. Rect updates now transfer affected VDP1 words/rows and only intersecting prepared regions, without reallocating VRAM. The scene now measures actual VDP1 world commands using a counter delta around the synchronous face flush, including partial emissions on a failed flush; this excludes earlier raw and cached-view commands. Next: hardware-side partial-update validation and canonical cache submission.

**M2 — Dependency isolation (in progress):** the shared fixed-point math implementation and its host-testable helpers now live under `src/core/math3d`, and physics no longer includes the math helpers through graphics. The CD Block HAL no longer weak-links or calls sat_audio_update. It exposes an optional borrowed per-block progress callback; nested reads return BUSY, and the CD streaming jukebox explicitly registers its audio service. Standalone CD clients have no implicit audio dependency. Mesh face lookup and scaled quad normals now live in `src/core/geometry/mesh_faces.hpp`, shared by collision and graphics; private physics sources no longer include graphics implementation headers. Public sat_quad3_t now lives in `saturn/geometry3d.h`; `saturn/mesh3d.h` exposes geometry and mesh operations without importing VDP1, while `saturn/mesh3d_draw.h` owns opt-in mesh draw contracts. The collision header imports only the geometry-only mesh header. The mesh construction/query C API and its pure implementation now live in `src/core/geometry`, while `sat_vdp1_draw_mesh` remains opt-in in graphics; a standalone host link gate compiles geometry without a renderer. Remaining: further narrow headers, typed assets, bounded memory ownership and additional L0/L1 link tests.

**M3 — Rendering integration (started):** preprojected static RGB cache items can opt into the existing bounded global face painter with an explicit linear camera-depth key and pass, so they interleave in the same far-to-near order with dynamic world faces; immediate cached replay and raw VDP1 remain independent. The queue copies each quad and reports queued versus actually emitted cache items separately. Projected cached RGB and indexed-textured surfaces now share the canonical painter and use one material-copy contract; indexed-tiled cache entries are normalized at submission to their preuploaded full texture, avoiding a borrowed tiled-descriptor lifetime through flush. Camera-bound view caches now have optional caller-owned exact camera snapshots (view-projection, pose, near depth and viewport); a stale view returns NOT_FOUND and clears its cached entry count, without requiring L1 clients to enable this higher-level contract. The `scene_cache_occlusion` example now bakes two camera-specific indexed8 surfaces and interleaves them with a moving RGB actor; camera pose changes invalidate/rebake the corresponding view only. The example is included in the all-examples build gate, and its C API usage has a standalone host syntax check. A synchronous flush now revalidates the full face queue's borrowed material descriptors before issuing any VDP1 command: a texture marked invalid after submission rejects the frame atomically, with host regressions for cached/indexed-tiled and world faces. This does not guarantee VRAM residency or prevent reuse of an address still marked valid. Camera-bound world-quad baking lives in an optional renderer-linked unit while the legacy view cache retains a standalone host-link gate. It projects and records linear W once; the scene's baked-item enqueue path reuses that key, and the mixed example no longer calculates depth on every frame. The scene facade now rejects an entire queue before any world emission if the projected one-command subset cannot fit the VDP1 command quota after HUD reservation and END; it reports budget_blocked_faces. Clipped/fallback geometry still has variable physical command counts: the optional L3 facade now checkpoints and rewinds its unsubmitted VDP1 command/Gouraud buffer on failure, preserving earlier raw commands; direct L1 face emission still exposes partial output. Managed cached textures have opt-in generation-verified ownership through painter flush, but their VRAM and palette storage are NOT pinned until VDP1 hardware finishes drawing. A BIOS-gated screenshot acceptance harness now captures behind/in-front actor frames and camera/zoom rebakes, but no screenshot is claimed visually verified without actually running that harness. Remaining: in-flight VRAM/CRAM ownership fences, real emulator captures/inspection and hardware timing.

**M4 — Physics/audio/parallel (partial):** generic parallel dispatch and profiling no longer know the Skybridge game flag. Audio now has independently host-tested bounded Sound RAM allocator, voice selection, sound/voice registries and shared PAL/NTSC service clock; the hardware service facade was split into API, sound, voice and private state compilation units. Physics uses optional stable collider-index scratch and conservative 64-bit mesh, moving and box bounds gates, plus an opt-in caller-owned BVH over finite static/kinematic colliders (see the structural spatial broadphase entry below). Without the BVH, and in its worst case, candidate iteration still visits every collider per sphere; sphere/sphere pairs and rotational CCD remain unsupported. Remaining: sphere/sphere pair scratch, long-run SH-2 hardware timings, SCSP in-flight resource ownership and on-device comparisons.

**M5 — Breaking migration and cleanup (partial):** generic library and per-example object/ROM variants are keyed by effective flags; the library build excludes example-generated-header paths. Parallel batches have no discarded local ordering scratch. Remaining: reconcile older docs/tests and any duplicated engines still found by repository-wide audits; run an actual emulator capture and stock-hardware acceptance separately.

**Every gate:** run host tests, Saturn cross-builds, representative example builds, available emulator checks, and collect command counts, memory budgets, and timing where relevant. Stock-hardware validation is a separate gate and must not be claimed without evidence. Do not publish a numerical speedup without measurements. A completed high-level feature must not break a standalone lower-level consumer.

## 8. Immediate first-slice implementation details

- Asset insertion scans every live slot for a normalized-path collision before choosing the earliest free slot; a hole cannot hide a later duplicate.
- Manifest preflight normalizes each path and checks all previous paths and live entries before inserting anything, keeping two bounded path buffers rather than allocating a large array on the Saturn stack.
- Screen sprite positioning consumes the active configured width/height and reuses the same screen-to-native helper as scaled sprites.
- Host regressions cover an earlier freed slot, different textual representations of one path, manifest non-mutation on rejected entries, successful valid manifests, and screen centering with two configured resolutions.

**Known limitation:** texture full and rect updates now preflight every CRAM/VRAM transfer (parent and affected prepared regions) before their first write, so a rejected update changes nothing, including caller-owned pixels; NEEDS_RECOVERY remains only for a transfer failing after that preflight, which today's CPU copies cannot, and is not a hardware rollback. Batch release takes the scene and records its failure in the frame; independently initiated low-level operations remain outside the optional L3 contract. Successful face dispatches are separately counted from physical VDP1 command deltas; immediate cached-view replay remains independent of that delta; opt-in queued cached RGB items are included in the scene flush delta. Direct L1 draws intentionally remain separate from the opt-in globally sorted L3 painter. Audio timing covers PAL/NTSC through its shared service clock; real hardware needs verification. VRAM writes remain irreversible; command-table submission and texture rewrites wait for the VDP1 to finish drawing (EDSR.CEF, bounded), but a texture destroyed mid-frame is not tracked per command. The physics candidate loop is O(spheres × colliders) unless the opt-in BVH is bound (whose worst case is the same). The CD/audio symbol dependency is removed; the optional callback still needs emulator/audio-streaming validation for reentrant workload combinations.

**Skybridge decoupling (profiling):** generic executor, scene preparation, painter and VDP1 no longer inspect the game-specific `SAT_SKYBRIDGE_VALIDATION`; they are built with opt-in `SAT_PROFILE_METRICS`. The game's own validation switch remains game-local. Effective-flag-specific build object/ROM variants now isolate game and generic library compilation.

**Batch painter DRY cleanup:** generic parallel preparation no longer allocates, publishes, or computes local ordering buffers. Source-order faces and depth keys merge once into the final painter; every example and host test now uses the reduced breaking batch contract.

**Limitation pass 2026-09-25 (phase A):** released voices are muted before key-off; `sat_music_seek`; stereo stream channels key on with one KYONEX (they were ~290 samples apart); CD progress-hook failures are counted; texture updates preflight and fence on VDP1 draw end; batch release records frame errors; the painter key has 24 depth bits (4096 units, pass max 255); builds of one example serialize under an flock; Slave completions are counted (the "zero Slave ticks" was an executor bug, not Ymir).

**Per-pass painter buckets and RGB clipping:** the scene painter buckets each live pass over its own depth span (`paint_order_grouped_buckets`), so adding a pass no longer widens every depth bucket to half a world unit; one pass costs exactly the single-range sort. RGB faces that cannot be emitted from their projection are near/screen-clipped through the same path as indexed solid faces (`sat_draw_polygon_quad3`) instead of being counted as skipped; a clipped Gouraud face is drawn flat.

**Pure-model link isolation:** VDP1 texture uploads now live in an optional `model_upload.cpp` unit; validation/geometry/animation tests link only `model.cpp`. The model-upload host test links the upload unit and supplies mocks for the INDEX8 and LUT4 hardware functions.

**Audio separation (first slice):** the bounded Sound RAM allocator is now an independent caller-owned pool, with standalone host tests for alignment, fragmentation, allocation slots, release and accounting. Sound/voice/clock orchestration still needs full splitting into separate compilation units.

**Physics opt-in type broadphase (first slice):** world_step now supports caller-owned collider-index scratch built in one source-order pass per tick, avoiding dynamic-sphere scans inside every CCD/solver iteration. The default direct world remains unchanged; this is type filtering, not a geometric spatial broadphase.

**Camera-coherent L3 cache path:** the scene can now queue a complete camera-verified preprojected view atomically, checking the scene's camera matrix/eye, the cache's full camera snapshot, baked linear depth flags and face capacity. Cache misses remain recoverable without poisoning the current frame; the lower-level item submission and raw draw paths stay independent.

**Sound RAM allocator complexity:** allocation slots now retain stable IDs in a caller-owned offset-sorted index. The first-fit free-range scan is linear in live blocks (no rescanning all allocations per gap), with O(C) insertion/removal for fixed capacity C; fragmentation ordering and reuse have host regressions.

**Audio voice policy (first slice):** free-slot selection, priority-based stealing and oldest-voice tie-breaking now live in a standalone pure policy, with host regressions. SCSP key-on/off, voice lifetimes, sound registry and clock remain in the audio service and are still candidates for independent modules.

**Build-profile isolation:** all game and asset objects plus ROM artifacts have variant-specific paths keyed by effective C/C++/ASM compiler flags and boot profile; reusable library objects depend only on generic metric/fault flags. Public `build/<example>.iso` and other root artifacts are republished from the selected variant, never used as build inputs. Generated asset C/H source staging is still per example, while compiled asset objects are per variant.

**Header isolation:** the shared library now compiles without the example-generated-header include path. Build profile behavior, reusable library keys, public artifact exports and the remaining shared source-generation concurrency limitation are documented in `docs/BUILD_PROFILES.md`.

**Audio service-clock separation:** the reconciliation of app frames with polled VBlank edges now lives in a standalone caller-owned clock policy. Host tests exercise held-high VBlank, synchronous-I/O stalls, app-frame catch-up and 32-bit wrap; playback still owns hardware polling and streaming dispatch.

**Sound registry separation:** pure bounded sound-slot generation, stale-handle rejection, activation and invalidation now belong to `sound_registry.hpp`. The playback facade continues to own upload/unload transactions and hardware interactions; host tests cover reuse, reset, out-of-range and generation wrap.

**Voice registry separation:** bounded voice-slot identity, handle generation, reset, release and active counts now reside in a pure caller-owned registry. The shared nonzero generation policy serves sound and voice handles; SCSP slot configuration, keying, and frame-expiry scheduling remain hardware orchestration, with host regressions for stale handles, slot reuse and wrap.

**Audio service compilation-unit split:** the resident playback facade has been separated into `api.cpp` (lifecycle, servicing, statistics), `sound.cpp` (sound upload/unload transactions), `voice.cpp` (SCSP voice operations), and `state.cpp` (service-owned bounded storage and helpers), linked by a private `state.hpp`. Pure clock, allocator, selection and registry policies stay hardware-independent and independently host-tested. No game-specific code or fallback allocation has been introduced.

**Opt-in VDP1 logical texture owner gate:** the high-level `sat_scene_bind_managed_textures` / `sat_scene_queue_managed_camera_view` adapter records one caller-owned owner span (face range, slot/generation from the existing logical texture registry) per queued view; face records carry no owner data, and the verifier runs once per span, keeping the per-face hot path unchanged. The L1 painter injects an optional owner verifier and rejects the entire painter before emission when a handle is destroyed/reused, even when the recycled native descriptor reports valid. Raw materials are still caller-owned, and no generic renderer or game depends on the texture registry. The gate cannot pin VRAM after flush until the hardware finishes processing commands; callers must retain in-flight ownership.

**Transactional L3 command-list emission:** the existing HUD/safe-face admission gate is complemented by an opt-in VDP1 staged command checkpoint. If variable-cost clipped geometry exhausts the command list, the whole scene's commands and Gouraud tables rewind without disturbing earlier raw draws or the HUD quota. Low-level face submission stays independent and can still report partial output. This is work-RAM staging rollback, not reversal of already committed VDP1/VDP2 hardware state.

**Unified resident-voice clock:** lifetime calculations now use the actual 50/60 Hz display rate and the same service-frame timeline as PCM streaming. The pure policy covers CD-read/VBlank stalls, timestamp reconciliation, ceiling duration, and 32-bit frame wrap in host tests; no audio hardware is mocked by the policy.

**Non-destructive failed voice steal:** `choose_voice` is now side-effect-free, and the playback facade only invalidates the prior handle/counts a steal after SCSP `configure_slot` accepts the replacement. HAL validates before any key-off; the successful configure already keys off its slot, avoiding a redundant second hardware transition. Host transaction tests cover refusal retaining the old voice, successful reuse, free-slot playback, and PAL/CD-stalled expiry.

**Finite-mesh conservative broadphase:** registration now caches immutable reference-mesh AABB extrema for static, grid-backed and kinematic colliders. Discrete sphere contacts (in local coordinates for translating/rotating meshes) and static mesh CCD use 64-bit, inclusive bounding checks to skip provably distant expensive mesh tests without reordering any possible contact; planar colliders, kinematic sweeps, and the independent opt-in mesh grid remain unchanged.

**Translating-sweep conservative broadphase:** the kinematic box and kinematic mesh CCD narrowphases now check 64-bit inclusive swept sphere/reference AABB overlap before casting. Motion is subtracted in the collider's start/reference space and pre-existing overflow validation still executes first; host regressions verify distant moving actors and retain existing nearby CCD contact tests.

**Whole-view camera snapshot integrity:** the canonical scene keeps copies of target, up and lens parameters in addition to its painter-owned eye and view-projection matrix. The L3 cache bridge rejects a camera mutated after scene begin even when its matrix/eye remain unchanged, eliminating mixed forward-depth keys across cached and dynamic faces. Host regressions cover target and aspect drift before cache lookup.

**Camera-view queue transaction:** full-view queue admission now restores its original face and queued-item counts when any individual baked material enqueue unexpectedly fails, preserving previously queued geometry. This closes the partial-queue case after initial depth/capacity preflight; host regression injects failure on the second view item.

**Compound box admission transaction:** a multi-face indexed box now restores its original painter count and cull/clip counters if a later face projection fails. Existing queued faces remain untouched; a host regression injects failure on the second box face.

**Mesh instance admission hardening:** instance submission now checks nonzero face and vertex counts against the declared backing capacities before projection/index reads, and restores its own queued face/cull/clip state on any late append error; tests cover malformed mesh capacities and zero counts.

**Finite-box conservative rejection:** iterative sphere/box narrowphase now excludes provably distant static and kinematic AABBs before per-axis contact calculations. A reusable 64-bit inclusive center/half-extents gate preserves touching contacts and avoids fixed-point overflow at coordinate extremes; infinite planes remain unaffected. This saves narrowphase work but does not replace a spatial index or change O(actors × spheres).

**Deterministic occlusion harness gate:** `harness/run-scene-cache-occlusion.ps1` drives a static cached checkerboard wall and moving RGB actor across two camera and zoom states, storing four compositor PNGs plus injected-guest proof. The optional screenshot test asserts additional visible red actor pixels after the actor moves ahead of the near wall and distinct camera/zoom images; a BIOS-free CI step validates its synthetic red-pixel mask only. Actual emulator images remain unverified until someone runs the BIOS-backed harness and inspects captures.

**Structural spatial broadphase (opt-in BVH):** caller-owned BVH nodes, source-ordered fallback plane indices and bounded candidate IDs now prune finite static/kinematic boxes and meshes before expensive CCD/discrete narrowphase. Full-tick swept bounds include kinematic translation and conservative rotational-mesh envelopes; 64-bit inclusive world bounds and deterministic actor-ID reordering preserve eligible contacts and ties. Host tests compare legacy and indexed worlds and check distant-collider pruning. Mesh-face grids remain independent; rotational CCD and sphere/sphere collisions remain unsupported. See `docs/PHYSICS3_WORLD_SPATIAL_BVH.md`.
